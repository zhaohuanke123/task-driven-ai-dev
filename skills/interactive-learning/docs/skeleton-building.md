# 骨架构建机制（大材料精读）

> **本文档说明如何对整本书/长文档等大块材料做结构化精读，生成可回溯原文的骨架，作为课程生成的原料。**
>
> **AI读取时机：** source-management 判定来源为大块材料时

---

## 核心问题

当来源是一整本书 / 长文档 / 多篇论文时，普通的"提取相关内容"不够——材料太大，直接生成课程容易丢失结构、无法回溯原文。

**解决方案**：先用并行 agent 把大材料精读成**骨架**——每个论点带原文定位，标注可跳过内容，建立部分间关联。后续课程都基于骨架生成。

---

## 触发条件

骨架构建是**大材料专用**的，零散材料不需要。

| 来源类型 | 是否构建骨架 | 说明 |
|---|---|---|
| 整本书（PDF/MD，长篇） | ✅ 构建 | 结构复杂，需精读 |
| 长文档 / 多篇论文 | ✅ 构建 | 量大，需结构化 |
| Word 文件 | ✅（先转 MD） | 用 `scripts/convert_docx_to_md.sh` 转 MD 再构建 |
| 零散 Obsidian 笔记 / 网页 | ❌ 不构建 | 直接走 source-management 提取 |

**判断标准**：材料是否大到需要"先提炼结构再教学"。小材料直接用；大材料先建骨架。

---

## 核心原则

**每个论点必须能精确回溯原文**

没有定位的骨架是糊弄式总结，无法验证。回溯原文有两种载体：

- **原文行号**（`行 491-503`）——适用于本地 MD/TXT 文件
- **Obsidian 块ID**（`[[笔记#^block-id]]`）——适用于 Obsidian 笔记（见 `source-management.md`）

两者理念一致：让每个论点都能跳回原文核对。

---

## 骨架文件结构

产物：`{主题}/骨架/骨架_第N部分.md`

```markdown
# 第N部分 标题

## 核心论点

### 论点1：[一句话概括]
- 原文位置：行 XXX-XXX（或 [[笔记#^block-id]]）
- 关键内容：[具体描述]
- 关联概念：[相关概念名]

### 论点2：[一句话概括]
- 原文位置：行 XXX-XXX
- 关键内容：[具体描述]
- 反常识点：[如果有]

## 可跳过内容

### 实验细节
- 位置：行 XXX-XXX
- 原因：对理解核心概念无帮助，只需知道结论

### 背景介绍
- 位置：行 XXX-XXX
- 原因：与正文重合90%，冗余

## 本部分与整体的关系

- 前置：[需要先理解哪些部分]
- 后续：[为哪些部分铺垫]
- 核心贡献：[本部分解决什么问题]
```

---

## 示例：《思考，快与慢》第5章

```markdown
# 第5章 认知放松

## 核心论点

### 论点1：认知放松让人更容易相信
- 原文位置：行 491-503
- 关键内容：又累又饿的保释官容易否定保释申请。严肃的职业判断被血糖决定。
- 反常识点：你的"深思熟虑"可能只是今天没吃午饭。

### 论点2：重复曝光效应
- 原文位置：行 521-535
- 关键内容：反复接触某个刺激会让人产生好感，即使没有意识到。
- 关联概念：系统1的"熟悉即安全"机制

### 论点3：真相错觉
- 原文位置：行 548-562
- 关键内容：如果某个陈述容易理解，人们倾向于相信它是真的。
- 反常识点：清晰表达 ≠ 正确观点

## 可跳过内容

### 保释官实验详细数据
- 位置：行 495-498
- 原因：只需知道结论"饥饿影响判断"，数据细节不重要

### 重复曝光实验历史
- 位置：行 523-530
- 原因：历史背景，不影响理解核心机制

## 本部分与整体的关系

- 前置：第1-3章（系统1/2基础）
- 后续：第11章（锚定效应）
- 核心贡献：揭示系统1的"认知放松"机制，解释为什么我们容易被欺骗
```

## 骨架生成流程

### Step 1：并行精读

材料较大时，发送多个 agent 并行读取，每个负责一部分：

| Agent | 负责范围 | 任务 |
|-------|---------|------|
| Agent 1 | 前 1/4 | 提取核心论点 + 原文定位 |
| Agent 2 | 第 2 个 1/4 | 提取核心论点 + 原文定位 |
| Agent 3 | 第 3 个 1/4 | 提取核心论点 + 原文定位 |
| Agent 4 | 最后 1/4 | 提取核心论点 + 原文定位 |

> 材料不大（如单篇长文）可单 agent 顺序读取，不必强行并行。

### Step 2：合并骨架

将各 agent 产出合并，统一格式。

### Step 3：标注可跳过

识别：实验细节（只留结论）、背景介绍（与正文重合）、附录冗余。

### Step 4：建立关联

标注各部分间的前置/后续关系。

---

## 骨架质量检查

| 检查项 | 标准 | 不合格示例 |
|-------|------|-----------|
| 原文定位 | 每个论点必须有行号或块ID | "认知放松影响判断"（无定位） |
| 一句话概括 | 简洁明了 | "这章讲了好多东西" |
| 反常识点 | 标注出来 | 只写"这章很重要" |
| 可跳过标注 | 附理由 | "这部分可跳过"（无理由） |

---

## 与 source-management 的关系

骨架构建是 source-management 的**大材料深化分支**：

```
来源材料（source-management.md）
    │
    ├── 零散笔记/网页 → 直接提取相关内容 → 生成课程
    │
    └── 大块材料（整本书/长文档）
        ├── （Word 先转 MD）
        ├── 构建骨架（本机制）
        └── 基于骨架 + 诊断报告 → 生成课程
```

---

## 注意事项

- 骨架长度：约为原材料的 1/3 ~ 1/4
- 保留：核心论点 + 反常识点 + 关联关系
- 删除：实验细节 + 背景介绍 + 冗余附录
- 必须有：每个论点的原文定位（行号或块ID）
