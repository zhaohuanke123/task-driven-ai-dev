# 盲点诊断机制

> **本文档说明如何在开始学习前探测用户的理解盲点，为学习路径规划提供依据。**
>
> **AI读取时机：** 用户发起学习主题、且非纯新手时（见下方触发条件）

---

## 核心问题

用户对某主题"以为懂了其实没懂"的地方，才是最该学的。直接按主题默认顺序规划路径，会浪费时间在已掌握的内容上、漏掉真正的盲点。

**解决方案**：在生成第一课前，先用 4 道诊断题探测用户对各知识点的真实掌握等级，据此重排学习路径——已掌握的跳过，真正的盲点优先。

---

## 触发条件

诊断是**可选的**，避免给纯新手加重流程。

| 用户表现 | 是否诊断 | 说明 |
|---|---|---|
| "我要学《X》"（带书/材料） | ✅ 推荐诊断 | 已有材料，多半有基础，值得查漏 |
| "我对X有基础，帮我查漏" / "我想精进X" | ✅ 推荐诊断 | 用户自述有基础 |
| "我想学X" / "教我X"（纯新手，无材料） | ⚠️ 可跳过 | 从零开始，直接规划默认路径 |
| 用户拒绝 / 说"不知道" | ⚠️ 可跳过 | 用默认路径，进度.md 标注"未诊断" |

**判断标准**：用户是否对该主题已有一定认知。有 → 诊断收益高；无 → 诊断无意义（答不上来）。

---

## 诊断题设计

诊断题不是考试，是探测盲点。目标是找出"你以为懂了其实没懂"的地方。

### 四道题的分工

| 题号 | 目的 | 设计方向 |
|-----|------|---------|
| Q1 | 基础概念理解 | 问核心定义，看是否有误解 |
| Q2 | 应用场景判断 | 问实际案例，看能否正确应用 |
| Q3 | 反常识探测 | 问容易犯错的地方，暴露盲点 |
| Q4 | 个人痛点定位 | 问具体困境，定制学习路径 |

### 好的诊断题特征

1. **不考记忆** - 不问"第3章讲了什么"，问"你怎么理解XX概念"
2. **允许犯错** - 错误回答比正确回答更有价值（暴露盲点）
3. **有陷阱** - 设计常见误解，看用户是否掉进去
4. **关联实际** - 问用户的具体场景，而非抽象理论

### 示例

#### 《思考，快与慢》

```
Q1: 你对系统 1 / 系统 2 的理解是什么？
→ 探测：是否把系统2当成"更好"（常见误解）

Q2: 什么时候你会用"直觉"做决定？什么时候会"深思熟虑"？
→ 探测：是否意识到两种模式的切换机制

Q3: 球拍和球总价 1.10 美元，球拍比球贵 1 美元，球多少钱？
→ 探测：系统1是否自动蹦出错误答案（10美分）

Q4: 你最近做过什么重要决定？后悔吗？为什么？
→ 探测：决策盲点，定制学习重点
```

#### 《原子习惯》

```
Q1: 你认为习惯形成的核心机制是什么？
→ 探测：是否理解"提示-渴望-反应-奖励"循环

Q2: 为什么"靠意志力坚持"往往失败？
→ 探测：是否理解意志力是消耗品，不是习惯引擎

Q3: 你有没有"想养成但一直失败"的习惯？分析原因？
→ 探测：是否把失败归因于"不够努力"（错误归因）

Q4: 你想成为什么样的人？现在的习惯和这个身份一致吗？
→ 探测：身份认同与习惯的关系
```

#### 《非暴力沟通》

```
Q1: 当别人批评你时，你的第一反应是什么？
→ 探测：是否进入防御/反击模式（常见反应）

Q2: "你总是迟到"这句话，你听到的是什么？
→ 探测：是否能区分观察vs评论

Q3: 你最近一次生气是因为什么？对方做了什么？
→ 探测：是否能找到背后的未满足需求

Q4: 你最想改善的一段关系是什么？卡在哪里？
→ 探测：定制学习重点
```

## 掌握等级判定（对齐 L1-L5）

诊断每个知识点时，用与检查站验证（见 `feynman-verification.md`）相同的 L1-L5 语言，保证诊断与后续验证口径一致：

| 等级 | 判断标准 | 路径规划处理 |
|-----|---------|------|
| L1 复述 | 答不出 / 只能说关键词 | 🔴 重点学（盲点） |
| L2 解释 | 能说但说不清、有误解 | 🔴 重点学（盲点） |
| L3 应用 | 能举例、能处理变体 | ⬜ 跳过 / 快速过 |
| L4 迁移 | 能向新手解释 | ⬜ 跳过 |
| L5 创造 | 能主动关联其他知识 | ⬜ 跳过 |

**路径规划原则**：L1-L2 的知识点优先排在前面的课程；L3+ 的标记为"已掌握/跳过"，不单独设课。

---

## 诊断流程

```
用户发起学习主题（非纯新手）
    │
    ├── 判断是否触发诊断（见触发条件表）
    │
    ├── 生成 4 道诊断题（按四题分工）
    │
    ├── 等待用户回答（5-10 分钟）
    │
    ├── 逐题判定掌握等级（L1-L5）
    │
    ├── 生成诊断报告 → {主题}/诊断报告.md
    │
    ├── 在 进度.md 恢复点引用诊断报告
    │
    └── 交回主流程：按盲点重排路径、生成第一课
```

---

## 诊断报告格式

产物：`{主题}/诊断报告.md`

```markdown
# 【主题】诊断报告

## 诊断时间
YYYY-MM-DD

## 回答分析

### Q1：[问题]
- 用户回答：[摘要]
- 掌握等级：L?
- 暴露盲点：[具体描述]

### Q2-Q4：...

## 综合诊断

### 盲点排序（按严重度）
1. [盲点1]（L1）- 来自Q3 - 🔴 重点学
2. [盲点2]（L2）- 来自Q1 - 🔴 重点学
3. ...

### 已掌握（可跳过）
- [知识点]（L3+）

## 对路径的建议
- 最需要学的：[对应知识点]
- 可跳过的：[对应知识点]
```

---

## 注意事项

- 诊断题数量：4 道（覆盖全面又不疲劳）
- 时间控制：5-10 分钟完成
- 不评判对错：只记录掌握等级
- 错误更有价值：暴露盲点是诊断的核心目的
- 用户可随时说 `重新诊断` 清除旧报告重测

---

## AI 执行检查清单

- [ ] 判断用户是否非纯新手（决定是否诊断）
- [ ] 生成 4 道题，覆盖四题分工
- [ ] 逐题判定 L1-L5 等级
- [ ] 生成诊断报告到 `{主题}/诊断报告.md`
- [ ] `进度.md` 恢复点引用诊断报告
- [ ] 把盲点（L1-L2）反馈到路径规划
