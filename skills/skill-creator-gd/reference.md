# Skill 详细参考

## Frontmatter 完整字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | string | 显示名称。省略则用目录名。仅小写字母、数字、连字符，最长 64 字符 |
| `description` | string | 功能与使用时机描述。首个用例放最前面。强烈推荐提供 |
| `when_to_use` | string | 额外触发条件（触发短语、示例请求）。与 description 共享 1,536 字符上限 |
| `argument-hint` | string | 自动补全时的参数提示，如 `[issue-number]` 或 `[filename] [format]` |
| `arguments` | string/list | 命名位置参数，对应正文中的 `$name` 替换 |
| `disable-model-invocation` | boolean | `true` = 禁止 Claude 自动加载。有副作用的操作务必设为 true。默认 `false` |
| `user-invocable` | boolean | `false` = 从 `/` 菜单隐藏。纯背景知识适用。默认 `true` |
| `allowed-tools` | string/list | skill 激活时 Claude 可免确认使用的工具 |
| `model` | string | skill 激活时使用的模型。接受 `/model` 相同的值，或 `inherit` 保持当前模型 |
| `effort` | string | 覆盖 effort 级别：`low`、`medium`、`high`、`xhigh`、`max` |
| `context` | string | 设为 `fork` 在隔离子代理中运行 |
| `agent` | string | `context: fork` 时使用的子代理类型（`Explore`、`Plan`、自定义代理等） |
| `hooks` | object | 限定于此 skill 生命周期的钩子 |
| `paths` | string/list | Glob 模式，限制仅在处理匹配文件时激活 |
| `shell` | string | 动态注入使用的 shell：`bash`（默认）或 `powershell` |

## 调用控制矩阵

| 配置 | 用户可调用 | Claude 可调用 | 上下文行为 |
|------|-----------|-------------|-----------|
| 默认 | 是 | 是 | 描述始终在上下文，正文调用时加载 |
| `disable-model-invocation: true` | 是 | 否 | 描述不在上下文中，用户调用时加载 |
| `user-invocable: false` | 否 | 是 | 描述始终在上下文，调用时加载正文 |

### 选择建议

- **默认**：大多数引用型 skill，Claude 按需自动加载
- **`disable-model-invocation: true`**：部署、提交、发送消息等有副作用的操作
- **`user-invocable: false`**：纯背景知识（如领域术语表），不需要用户手动触发

## 作用域与优先级

| 级别 | 路径 | 作用域 |
|------|------|--------|
| 企业级 | 通过托管设置部署 | 组织内所有用户 |
| 个人级 | `~/.claude/skills/<name>/` | 你的所有项目 |
| 项目级 | `.claude/skills/<name>/` | 仅当前项目 |
| 插件级 | `<plugin>/skills/<name>/` | 插件启用范围 |

优先级：企业级 > 个人级 > 项目级。插件级使用 `plugin-name:skill-name` 命名空间，不会冲突。

### 自动发现

- 项目级 skill 从启动目录的 `.claude/skills/` 向上查找到仓库根目录
- 编辑子目录文件时，也会按需发现嵌套的 `.claude/skills/`
- `--add-dir` 指定的目录中的 skill 也会被加载
- 文件变更实时检测，无需重启

## Skill 内容生命周期

1. **调用时加载**：正文作为单条消息进入对话，此后一直保留
2. **不重新读取**：后续轮次不会重读文件，变更需重新调用
3. **自动压缩**：上下文压缩时每个 skill 保留前 5,000 token
4. **共享预算**：所有被调用的 skill 共享 25,000 token
5. **最新优先**：从最近调用的 skill 开始填充预算，较早的可能被完全丢弃

## 可见性覆盖

在 `settings.json` 中通过 `skillOverrides` 控制：

```json
{
  "skillOverrides": {
    "skill-name": "on"
  }
}
```

| 值 | Claude 可见 | `/` 菜单可见 |
|----|-----------|-------------|
| `"on"` | 名称 + 描述 | 是 |
| `"name-only"` | 仅名称 | 是 |
| `"user-invocable-only"` | 隐藏 | 是 |
| `"off"` | 隐藏 | 隐藏 |

## 两种 Skill 类型详解

### 引用型（Reference）

添加 Claude 应用于当前工作的知识。

- **适合**：编码规范、设计模式、领域知识、风格指南、术语表
- **运行方式**：内联运行，与对话上下文并行使用
- **典型设置**：默认调用控制，正文以规则/规范/知识要点为主
- **正文风格**：声明式 — "规则是X"、"模式是Y"

### 任务型（Task）

给 Claude 逐步执行的操作指令。

- **适合**：部署、提交、代码生成、批量操作、报告生成
- **通常设置**：`disable-model-invocation: true`
- **有副作用的操作务必**设为手动调用
- **正文风格**：指令式 — "做X"、"运行Y"、"检查Z"
- **可选**：`context: fork` 隔离执行，`allowed-tools` 预授权工具

## Skill 与 CLAUDE.md 的区别

| 维度 | CLAUDE.md | Skill |
|------|-----------|-------|
| 加载时机 | 每次会话自动加载 | 按需加载（描述始终在上下文） |
| Token 开销 | 全量持续占用 | 正文仅在调用时占用 |
| 适用内容 | 项目事实、团队约定 | 操作流程、多步骤任务、参考材料 |
| 调用方式 | 自动 | 自动或 `/name` 手动 |
| 文件结构 | 单文件 | 目录结构，支持辅助文件 |
| 参数化 | 不支持 | 支持 `$ARGUMENTS`、命名参数 |
| 子代理 | 不适用 | 支持 `context: fork` |
| 动态内容 | 不支持 | 支持 `` !`command` `` 预处理 |

**判断原则**：当 CLAUDE.md 中的某段内容从"事实陈述"变成"操作流程"时，就该提取为 Skill。

## 提示词编写技巧（Skill 正文优化）

Skill 正文本质上是给 Claude 的提示词。以下技巧可提升正文质量：

### 描述精准（而非笼统）

```
差：帮助处理代码
好：总结未提交的变更并标记风险项。当用户询问改了什么、需要提交信息或审查 diff 时使用
```

### 指令式而非说明式

```
差：错误处理是一种在代码中捕获异常的机制，通常使用 try-catch 语句...
好：所有公共 API 端点必须包含错误处理，使用 try-catch 捕获异常并返回统一错误格式
```

### 用示例引导格式

在正文中直接给出期望的输出格式示例，比抽象描述更有效：

```markdown
## 输出格式

按以下格式输出：

### 变更摘要
- **文件**：路径
- **类型**：新增/修改/删除
- **说明**：一行描述
```

### 角色定位（可选）

当 Skill 需要特定专业视角时，在正文开头设定角色：

```markdown
作为代码审查专家，审查以下变更...
```

### 思维链引导（复杂任务）

对需要多步推理的复杂任务，引导 Claude 分步思考：

```markdown
分析时按以下步骤：
1. 先识别变更的影响范围
2. 评估每个变更的风险等级
3. 检查是否存在遗漏的修改
4. 最后给出综合评估
```

## 语言表达规范详解

以下规则适用于所有 Skill 正文，确保信息密度高、无冗余。核心原则：**每个词都问"去掉后命题内容是否改变？"不变则删。**

### 8类词汇冗余详解

#### 1. 虚词

"的"逐个判断，默认删，仅产生歧义时保留。"了"无体意义时删。形式动词一律删。

```
系统的功能→系统功能
进行了检测→检测
提供了支持→支持
予以删除→删除
```

#### 2. 回指

删除读者可从上下文推断的回指词。常见回指词：程序、系统、功能、该模块、该机制、该过程、本机制、本维度、本功能、本模块、本节、本文档、两者、所有…均、各项。

```
该模块处理数据→处理数据
本机制提供接口→提供接口
系统检测到变化后，系统触发处理→检测到变化后触发处理
```

#### 3. 框定

删除无信息修饰语。

```
相应的处理→处理
一定的条件→条件
相关的逻辑→逻辑
```

#### 4. 限定

不影响精确度时删。技术敏感限定词（严格/仅/唯一）保留。

```
特定的条件→条件
适当的配置→配置
仅服务端可调用→仅服务端可调用（"仅"有精确含义，保留）
```

#### 5. 量词

不影响精确度时删。精确计数保留。

```
一个回调→回调
一种策略→策略
重试3次→重试3次（精确计数，保留）
```

#### 6. 名词化还原

形式动词/介词框架包装→直接动宾。

```
对数据进行检测→检测数据
将计算完成→计算完成
实现X的功能→实现X
对X做出响应→响应X
```

#### 7. 框架词

紧凑化或删除。

```
在…情况下→当…/直接条件
在…基础上→基于…
通过…来实现→直接动词
将…作为…→直接作为
在…过程中→…全程/省略
避免X带来的Y问题→避免X（Y）
X既能A也能B→X可A或B
使得X能够Y→X可Y
```

#### 8. 从句

删"所"结构。

```
X所对应的Y→X对应Y
X所属的Y→XY
由X所决定的Y→X决定的Y
X所依赖的Y→X依赖Y
```

### 句法规则详解

#### 允许合并（需同时满足）

1. **直接因果/时序**
2. **同一执行步骤内**
3. **不模糊关键节点**

```
连动结构：检测触发处理 ✓
紧缩复句：超过阈值后进入疼痛状态 ✓
主语承前省略：检测受力，触发反应，达到阈值 ✓
```

#### 必须拆分

1. **独立事件无逻辑关联**
2. **主语转换**

```
系统处理数据生成报表。系统发送通知。→ 拆分（两个独立事件）
系统检测数据。用户查看结果。→ 拆分（主语转换）
```

#### 条件从句紧凑化

```
若鱼未处于力竭状态，则鱼体力瞬间恢复至 → 若未力竭则体力恢复至
当X满足条件Y时，执行Z操作 → X满足Y时执行Z
```

#### 重复主语省略

```
鱼体力上限与体型正相关；鱼体力上限与水温负相关
→ 鱼体力上限与体型正相关，与水温负相关
```

### 话题规则详解

句首必须是领域实体名词。

**禁止**：
- 回指壳：程序/系统/该功能/本机制/本维度/本模块/本节/本文档
- 主题标记：关于/对于/至于
- 元叙述：模块的作用是/功能提供

**例外**：需区分多个主体时可保留必要标识。

### 结构性优化详解

#### 列表折叠

嵌套列表 ≤3项，每项 ≤30字 → 合并为行内枚举。

```
- 近探测点：距离 = 身长 * 5
- 远探测点：距离 = 身长 * 10
→ 近/远探测点距离 = 身长 × 5/10
```

#### 参数同构合并

连续规则结构相同仅参数名不同 → 模板+参数差异表。

```
水深权重修正 = clamp(评分 * 0.8, 0, 1)
离钓竿权重修正 = clamp(评分 * 0.6, 0, 1)
→ 权重修正 = clamp(评分 × 系数, 0, 1)，系数：水深0.8 / 离钓竿0.6
```

### 应用示例

**优化前后对比**：

```
原始（冗余）：
"系统检测鱼嘴受力超过阈值。系统触发疼痛值累积。疼痛值达到阈值后进入疼痛回避状态。"

优化后：
"鱼嘴受力超过阈值，触发疼痛值累积，达到阈值后进入疼痛回避状态。"
（删回指"系统"，连动因果链合并，句首改为领域名词"鱼嘴受力"）
```

```
原始（冗余）：
"该模块的作用是对传入的数据进行相应的检测，在满足特定条件的情况下触发处理流程"

优化后：
"传入数据满足条件时触发处理"
（删回指"该模块"、删元叙述"的作用是"、名词化还原"对数据进行检测→检测数据"、删限定"相应的/特定"、框架词紧凑化"在…情况下→…时"）
```
